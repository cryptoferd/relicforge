HOW-TO · RC4.7B

From artwork to the forge.

Relic Forge is currently a release-candidate/testnet implementation. The canonical V1 contracts are not professionally audited and should not be described as mainnet-ready. Read permanent and irreversible actions carefully before signing.

01 · CONNECT AND SAVE

Connect your creator wallet.

Use an EVM wallet to sign into RelicForge Cloud. Cloud projects are scoped to the connected creator wallet so the editable Studio project can be reopened on another device. Downloaded backups remain a separate recovery path.

Starting a New Project clears the open workspace; it does not delete saved cloud projects or backups. Save before closing if the current work matters.

02 · ARTWORK

Build the layer stack your way.

Upload an organized folder, create empty layer categories and add traits later, or create a category from loose files. Categories and traits remain editable throughout the build, including renaming and reordering.

Optional full-canvas 1/1 artwork occupies its own collection recipe slot and bypasses normal layered rendering for that token.

03 · RARITY & METADATA

Percentages or exact counts.

Set rarity by percentages, exact amounts, tiers, or equal distribution. Auto Fill preserves values you entered manually and distributes only what remains.

Metadata controls can hide selected None traits globally, hide an entire rendered category from metadata, or hide an individual trait only on tokens that use it. Standalone 1/1s can override token name, description, and custom trait_type/value attributes.

04 · RULES

Define compatibility before generation.

Create compatibility and incompatibility rules between traits. Relic Forge warns about conflicts and can show examples of outcomes before the collection is finalized.

Rules are part of the deterministic generation input, so review them before sealing content.

05 · PREVIEW & AUDIT

Generate, inspect, curate.

The Preview step summarizes supply, layers, rules, manual recipes, duplicates, and exports. Collection Preview is paginated; Rarity Audit groups expandable trait categories.

Generation is deterministic from the chosen seed. Enter a seed manually, regenerate, or generate a new random 16-character alphanumeric seed. Export the final manifest before permanent steps if you want an independent record.

06 · FORGE

Create through canonical V1 infrastructure.

The canonical V1 Factory creates creator-owned Collection and ProjectData clones. Artwork/DNA are prepared for onchain storage, and Chainlink VRF is used for reveal randomness.

Choose Sponsored or Minter Supported Relic Forge platform fees. Content finalization does not turn minting on. Every new V1 collection begins with Master Mint OFF; the creator must explicitly arm it after checking the deployed collection.

Permanent actions: content sealing freezes canonical artwork/DNA/provenance. Controller renounce is irreversible and removes creator sale/content control defined by the contract. Verify addresses, phases, payout, royalties, reveal settings, and content before signing.

07 · MINT PAGE / UPCOMING

Publish the collection once.

The public V1 mint page uses the configured public and whitelist phase IDs. It reads phase state from the canonical collection and uses quoteMint() so the submitted value includes the creator price and any live Minter Supported platform fee.

Add collection and banner media, publish the mint page, and optionally enable Show on Upcoming Mints with a start date/time. The public Upcoming page and landing carousel reuse the same title, description, image, chain, contract, and mint-page link—no duplicate promo record is required.

08 · COLLABORATION

Share editing, never signing authority.

Add collaborator EVM wallets from the Collaboration dashboard and grant only the sections they need: Artwork & Layers, Rarity & Metadata, Trait Rules, Curation & Preview, Launch Setup, or Mint Page & Showcase.

Collaborators sign in with their own wallet. They never receive the creator private key, creator wallet impersonation, deployed NFT ownership, contract controller authority, or creator-only transaction signing.

Every collaboration save appends a version with actor wallet, changed sections, and a note. Creator rollback creates another new version and keeps all later history and historical artwork available.

REVEAL MODEL

Forge Reveal or Deferred Reveal.

Forge Reveal resolves random assignment as the mint-time forge flow completes. Deferred Reveal leaves minted tokens pending until a later reveal epoch. V1 uses fresh VRF requests, a global no-replacement recipe pool, no rerolls, bounded processing for large reveal epochs, and exact replay behavior if a callback must be recovered.

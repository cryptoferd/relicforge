Creator Guide

Relic Forge R12-v2 creates immutable EIP-1167 Collection, ProjectData, and MintPhases clones. Mainnet is not deployed or enabled in this build. This guide describes the certified Sepolia preproduction architecture used by the Creator UI.

Important: R12-v2 public collector mint-page publishing is intentionally disabled in Creator UI R1. The older V1 collector page does not understand Forge reservations, the separate MintPhases contract, or the request/replay/settle lifecycle. A dedicated V2 collector-page rewrite is required before publishing a V2 mint page.

Connect a wallet and save your project

Connect the EVM wallet that will own the creator controls. Cloud project saves are wallet-scoped. Downloaded project backups remain a separate recovery path. Founder Support can inspect an opted-in cloud project but never receives your private key or your onchain signing authority.

Add artwork

Upload an organized folder, create empty layers and add artwork later, add multiple traits to an existing layer, or create a category from loose files. Categories remain editable before the final onchain compile.

Set rarity and exact counts

Use percentages, exact quantities, manual token curation, or a collection manifest. Auto Fill preserves values you entered and distributes only the remainder. Optional full 1/1 artwork occupies its own recipe slot and can carry token-specific name, description, and metadata attributes.

Choose metadata visibility

You can hide selected None traits, hide a whole rendered category from metadata, or hide individual traits only on tokens that use them. These controls affect token attributes, not the visual render.

Build rules and preview

Resolve every rule, exact-count, and distribution conflict before launch. Preview the collection and compile the exact recipe set. Relic Forge validates recipes before the ProjectData content can be sealed.

Set collection identity, payout, and royalty

Confirm the name, symbol, description, maximum supply, payout receiver, royalty receiver, and royalty percentage. Creator proceeds are tracked separately from reveal funding. Withdrawing creator proceeds always sends them to the configured payout receiver.

Choose reveal mode

Deferred Reveal = 0. Hidden ERC-721s mint immediately. When you request reveal, one verified Chainlink word permanently fixes the collection-wide assignment permutation. There is no creator reroll.

Forge Reveal = 1. A collector mint creates a reservation instead of calling Chainlink. Reservations are batched, randomized later, and settled in deterministic order. A collector transaction may therefore succeed without immediately emitting the final NFT Transfer events.

Set Forge execution limits

Batch window controls how long a partial Forge batch can remain open before anyone may lock it. Full 20-NFT batches lock automatically. Maximum randomness cost per batch is an onchain ceiling. If the current request quote is above that ceiling, the randomness request reverts instead of silently overspending.

Choose the platform-fee model

Creator Covers Platform Fee pays the quoted fee at collection creation. That ETH enters the collection reveal hopper. Collectors do not pay a Relic Forge per-mint platform fee.

Collector Covers Platform Fee adds the active current fee to collector mints when the ETH/USD quote is healthy. If the quote is unhealthy, the current R12-v2 minter-supported path fails open to a $0 platform fee rather than blocking the collector mint.

Platform fee value first supports verified-randomness and reveal execution through the collection hopper and shared Reserve. Protected Reserve ETH is not releasable platform revenue. Only surplus above required Reserve safety can be released.

Configure Minting stages

R12-v2 stores mint-stage policy in the separate MintPhases clone, not in the Collection. Public and Approved Wallet stages can have their own price, time window, supply cap, wallet cap, access root, priority, and enabled state. The top-level Minting switch is also stored in MintPhases.

Forge the collection

The Factory receives one createCollectionV2(LaunchConfig) call and creates the Collection, ProjectData, and MintPhases clones. The Studio then writes artwork shards, metadata settings, traits, DNA shards, placeholder art, validates recipes, seals content, creates mint stages through MintPhases, and verifies the Collection/MintPhases binding.

Review the launch before enabling minting

Check the Collection, ProjectData, and MintPhases addresses, content seal, payout receiver, royalty receiver, reveal mode, fee mode, hopper state, batch window, randomness ceiling, and phase schedule. Relic Forge R1 does not publish a V2 collector mint page.

Forge Reveal execution

StageWhat happens
Collector mintCreates one or more reservations. No randomness-provider call occurs in the collector transaction.
Lock batchA 20-NFT batch locks automatically. A partial batch can be locked permissionlessly after the configured batch window.
Request randomnessAnyone may call requestRandomnessForBatch(batchId). Creator UI uses a conservative 1,500,000 gas limit. The Collection pays from its hopper first and may request only the exact bounded shortfall from Reserve.
Chainlink callbackThe adapter stores the exact verified word only. It does not call the Collection inside the Chainlink callback.
ReplayAnyone may call replayFulfillment(localRequestId). Creator UI uses a 1,000,000 gas limit and then verifies deliveredForLocalRequest(localRequestId) == true. A mined transaction alone is not treated as proof of delivery.
SettleAnyone may call settleReady(maxTokens). Ready reservations mint NFTs and receive unique recipes in batch order.

Deferred Reveal execution

Deferred mints create hidden ERC-721s immediately. When the creator calls requestDelayedReveal(), minting freezes until the exact verified word is delivered. Creator UI requests with a conservative 1,500,000 gas limit. After Chainlink stores the word in the adapter, replayFulfillment(localRequestId) delivers it to the Collection. Delivery permanently fixes the delayed permutation. There is no bounded per-token reveal-processing loop.

If delayed reveal happens before sellout, future mints irreversibly switch to Forge Reveal. Recipes already consumed by the delayed permutation are excluded from the future Forge pool.

Creator/team mint

creatorMint(address,uint32) is payable in R12-v2. In Collector Covers Platform Fee mode, MintPhases exposes creatorTeamFeeQuote(quantity). When the fee is active and the oracle is healthy, the creator/team mint pays approximately half of the current per-NFT platform fee. The Studio quotes this value and attaches it automatically.

Creator earnings

Collector sale proceeds do not become platform reveal funding. Deferred-mode sale proceeds accrue immediately after the hidden NFT mint succeeds. Forge-mode creator sale value stays in creatorEscrow while a reservation waits and moves to accruedCreatorProceeds when the reservation settles. Calling withdraw() sends only accrued creator proceeds to payoutReceiver.

Irreversible and security-sensitive actions

  • ProjectData content becomes immutable after sealContent().
  • Each Collection, ProjectData, and MintPhases clone is permanently bound to its implementation through EIP-1167 runtime bytecode.
  • Reveal mode is creator-selectable only while the collection is empty, except for the automatic Deferred-to-Forge transition after an early delayed reveal.
  • Permanent fee waivers and controller renunciation should be treated as irreversible.
  • FeePolicy treasury changes and Reserve revenue-treasury changes are separate two-step authority handoffs.
Security status: the R12-v2 stack has extensive automated and live Sepolia certification, including hostile cross-contract state-machine testing, but that is not a professional audit and does not prove the absence of vulnerabilities. Mainnet remains disabled.
